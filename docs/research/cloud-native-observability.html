📊 可观测性三大支柱

Metrics 指标

数值聚合，粗粒度。
典型工具：Prometheus
查询语言：PromQL
存储成本：低

Logs 日志

文本事件，细粒度。
典型工具：ELK, Fluent Bit
查询语言：ES DSL
存储成本：高

Traces 追踪

请求生命周期，中等粒度。
典型工具：Jaeger, OTel
查询语言：TraceQL
存储成本：中

💡 关键洞察：真正的可观测性价值在于信号关联——从指标发现异常、从日志定位根因、从追踪追溯完整请求路径。OpenTelemetry 正成为统一三信号的通用语言。

📝 ES Query DSL — 基础查询

match（分词全文搜索）

GET /logs/_search { "query": { "match": { "message": "error occurred" } } }

term（精确匹配）

GET /logs/_search { "query": { "term": { "status_code": 200 } } }

terms（多值匹配）

GET /logs/_search { "query": { "terms": { "status_code": [200, 201, 304] } } }

range（范围过滤）

GET /logs/_search { "query": { "range": { "@timestamp": { "gte": "now-7d", "lte": "now" } } } }

🔧 ES Query DSL — bool + 聚合

bool 组合查询

GET /logs/_search { "query": { "bool": { "must": [ { "match": { "title": "error" } } ], "filter": [ { "term": { "status": "active" } } ], "must_not": [ { "range": { "priority": { "gte": 5 } } } ], "should": [ { "term": { "tag": "critical" } } ] } } }

terms 聚合（分组统计）

GET /logs/_search { "size": 0, "aggs": { "by_status": { "terms": { "field": "status_code", "size": 10 } } } }

date_histogram（时间维度）

GET /logs/_search { "aggs": { "over_time": { "date_histogram": { "field": "@timestamp", "calendar_interval": "hour" } } } }

📝 PromQL 入门

Instant Vector（即时向量）

# 选择所有 http_requests_total 指标 http_requests_total # 带标签过滤 http_requests_total{job="api", method="GET"} # 标签匹配: = != =~ !~ {job="nginx", status=~"5[0-9]{2}"}

Range Vector（区间向量）

# 过去 5 分钟的数据 http_requests_total[5m] # 偏移 1 小时 http_requests_total offset 1h # rate: 每秒增长率 rate(http_requests_total[5m]) # increase: 区间增量 increase(http_requests_total[1h])

聚合操作

# 按服务分组 sum by(service) (rate(http_requests_total[5m])) # Top 3 topk(3, rate(http_requests_total[5m])) # P99 延迟 histogram_quantile(0.99, rate(duration_bucket[5m]))

布尔运算

# 算术 cpu_usage > 0.8 # 比较且保留原始值 cpu_usage > bool 0.8 # 逻辑 up{job="api"} or up{job="web"}

📈 Grafana — 统一可视化层

💡 核心角色

Grafana 是"查询+展示"引擎，不存数据。支持 40+ 数据源（Prometheus、ES、Loki、MySQL 等）。

Dashboard

创建面板 → 选择数据源 → 写查询 → 选图表类型 → 保存。支持 Variables 变量实现下拉过滤。

Explore

无需建 Dashboard，直接写 PromQL/ES DSL 查数据。支持 Mixed 同时查多个数据源。

Alerting

统一告警引擎，Slack/Email/Webhook/PagerDuty 等 20+ 通知渠道。

配数据源步骤：齿轮图标 → Data Sources → Add → 选 Prometheus → URL 填 http://localhost:9090 → Save & Test。

🔗 OpenTelemetry 统一标准

1800+
Contributors
#2
CNCF 项目规模
3
三大信号模型
  • 由 OpenTracing + OpenCensus 合并而来，CNCF 孵化项目
  • 三大信号数据模型：Traces（Span/TraceId）、Metrics（Counter/Histogram）、Logs（LogRecord）
  • 核心架构：Specification → SDK（自动/手动 Instrumentation） → Collector → Exporters
  • OTLP 协议（gRPC/HTTP）是统一传输格式，可输出到任何兼容后端

💨 Fluent Bit — 轻量日志采集

⚡ 极致轻量

C 语言编写，内存占用 ~650KB（Fluentd：~40MB，Logstash：1GB+），性能是 Fluentd 的 10-40 倍

Pipeline 六阶段

Input → Parser → Filter → Buffer → Routing → Output

支持 tail/cpu/tcp/syslog 等输入，ES/S3/Kafka/OTLP 等输出。

[INPUT] name tail path /var/log/nginx/access.log parser nginx [FILTER] name grep match * regex status 5[0-9]{2} [OUTPUT] name es match * host 192.168.1.100 index nginx-logs

🔬 Jaeger — 分布式追踪

💡 定位

CNCF 毕业项目，分布式追踪的后端存储与查询方案，原生支持 OTLP（v2+）。与 OpenTelemetry 深度集成。

架构组件

  • Collector: 接收 span 数据
  • Storage: ES/Cassandra/Badger
  • Query: 查询 API
  • UI: Web 界面

核心能力

  • TraceID 精准检索
  • 服务依赖关系图
  • Span 对比分析
  • 采样策略配置
  • 与 Grafana 集成
典型用法：OTel SDK 采集 span → OTel Collector 转发 → Jaeger 存储和展示。在 Jaeger UI 中按服务名搜索 trace，查看瀑布图定位慢调用。

🔄 项目关系与选型对比

竞争关系

  • Fluent Bit vs Logstash: FB ~650KB vs LS ~1GB+，性能差 10-40x
  • OTel Collector vs Fluent Bit: OTel 统一三种信号，FB 专精日志
  • Prometheus vs ES: 指标 vs 搜索，各有专攻

互补关系

  • Prometheus + Grafana: 黄金组合，指标采集 + 可视化
  • OTel + 任何后端: OTel 是通用采集层，可输出到 Jaeger/Prometheus/ES
  • Fluent Bit + ES: 日志采集 + 存储搜索
场景推荐方案理由
指标 + 告警Prometheus + Grafana成熟生态、最广泛采用
日志 + 搜索ELK Stack全文搜索不可替代
全栈可观测OTel + Grafana + Prometheus统一采集、统一可视化
已有 ES扩展 ES 生态降低学习成本
新项目OTel Collector + Grafana最现代方案

🏗️ 三种部署模式

🌱 轻量方案

适合：个人开发者 / 初创团队

  • Prometheus + Grafana（指标）
  • 或 ELK single-node（日志）
  • 单机部署，零运维

🏢 企业方案

适合：中型团队

  • ELK + Kafka（高可用）
  • 或 Prometheus HA + Grafana
  • OTel Collector 统一采集

☁️ 云原生方案

适合：大规模 Kubernetes

  • OTel Collector 采集层
  • Prometheus Operator 管理
  • Grafana 统一可视化
  • Jaeger 分布式追踪

🎯 总结

Elasticsearch + Kibana

日志存储与搜索标杆，ES Query DSL 掌握 match/term/bool/aggs 即入门

Prometheus + Grafana

指标采集黄金组合，PromQL 掌握 rate/sum by/histogram_quantile 即过关

OpenTelemetry

统一三信号的通用语言，OTel Collector 是关键中间层

Fluent Bit + Jaeger

轻量日志采集 + 分布式追踪，与 OTel 深度集成
