项目概览

llm-d 是一个高性能分布式推理服务栈，致力于在 Kubernetes 上实现 SOTA（State-of-the-Art）推理性能。项目基于 vLLM 作为默认模型服务器和引擎，通过 Kubernetes Gateway API 作为控制平面 API 和负载均衡编排器，为生产环境提供完善的分布式推理解决方案。

五大核心能力

1. 优化基线 (Optimized Baseline)

vLLM + Gateway API 负载均衡，配合前缀缓存感知路由、利用率负载均衡、多租户公平性和优先级调度。

2. P/D 分解 (Prefill/Decode Disagg)

将推理分为预填充和解码两阶段分别在独立实例执行，降低 TTFT、提升 TPOT，适合大模型和长提示场景。

3. 广域专家并行 (Wide Expert-Parallism)

支持 MoE 模型（如 DeepSeek-R1）的数据并行+专家并行部署，通过 fast accelerator networks 互联。

4. 分层 KV 缓存 (Tiered KV Cache)

GPU/CPU/SSD/Remote Storage 多层 KV 缓存 offload，提升前缀缓存命中率和内存利用率。

5. 工作负载自动扩缩容

SLO 感知成本优化的自动扩缩容，支持异构硬件和流量感知的变体自动扩缩容。

关键洞察

1. 企业级完整性：llm-d 不是简单的模型服务器，而是面向生产的完整分布式推理编排平台，从模型服务到路由调度再到自动扩缩容全覆盖。

2. Kubernetes 原生：深度绑定云原生生态，基于 Kubernetes Gateway API 实现服务网络抽象，适合企业级部署。

3. 与 vLLM 互补：llm-d 基于 vLLM 构建上层编排能力，不替代 vLLM 而是增强其生产部署能力。

核心术语

EPP (Endpoint Picker)

基于 Gateway API 的推理请求调度组件，决定请求路由到哪个模型服务端点。

P/D Disaggregation

Prefill/Decode 分离技术，将 LLM 推理的预填充阶段和解码阶段部署在独立实例。

TTFT / TPOT

Time To First Token / Time Per Output Token，衡量推理延迟的核心指标。

Wide Expert-Parallelism

MoE 模型的广度专家并行，结合数据并行和专家并行提升吞吐量。
