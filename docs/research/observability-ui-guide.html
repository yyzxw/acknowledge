可观测工具 UI 入门指南

Kibana · Grafana · Prometheus · Loki · Tempo — 从零开始上手操作

Kibana Grafana Prometheus Loki 日志 Tempo 追踪

1. Kibana — Elasticsearch 的可视化层

Kibana 是 Elastic Stack 的 UI 门户。部署好 ES 之后，访问 http://localhost:5601 进入 Kibana。你会看到左侧导航栏，几个最常用的入口：

🔍 Discover（数据探索）

这是最常用的页面，用来搜索和过滤 ES 中的原始数据。

  1. 进入左侧菜单 Discover
  2. 顶部选择数据视图（Data View），比如 logs-* 或 filebeat-*
  3. 搜索栏输入 KQL（Kibana Query Language）或 Lucene 语法检索日志
  4. 右侧显示时间轴分布和匹配的文档列表
  5. 点击某条文档可展开查看所有字段
入门技巧：搜索栏输入 status: >= 400 过滤所有 HTTP 错误请求； 输入 response_time: > 1000 查找响应超过 1 秒的请求。 日期范围在右上角选择。

📊 Dashboard（仪表盘）

将多个可视化图表组合到一个页面。

  1. 左侧菜单 Dashboard → Create dashboard
  2. 点击 Create visualization 选择图表类型
  3. 使用 Lens（拖拽式可视化编辑器）配置：
    • 拖拽字段到 X 轴（如 @timestamp）
    • 拖拽字段到 Y 轴（如 Count of records）
    • 拖拽字段到 Breakdown（如 status.keyword 按状态码分组）
  4. 保存后仪表盘自动刷新

🔧 Dev Tools（开发者工具）

直接向 ES 发送 REST API 请求，调试查询最方便。

打开左侧菜单 Dev Tools → Console，在编辑器中输入：

GET /_search
{
  "query": {
    "match": { "message": "error" }
  }
}

点击 ▶ 执行，右侧返回 JSON 结果。这是学习和调试 ES Query DSL 的最佳场所。

小贴士：Dev Tools 支持自动补全，输入 GET /<Tab> 会列出所有索引。 也可以只输入索引名查看 mapping：GET /my-index/_mapping

🗺️ 其他实用页面

页面用途入口
Index Management查看/管理 ES 索引Stack Management → Index Management
Data Views创建和管理数据视图（替代旧版 Index Pattern）Stack Management → Data Views
Maps地理数据可视化左侧 Maps
Alerts告警规则和通知左侧 Alerts and Insights
Stack Monitoring监控 ES 集群自身健康状态Stack Monitoring
常见误区：刚装好 Kibana 进入 Discover，如果看到 No results found，通常是： (1) 还没创建 Data View — 去 Stack Management → Data Views 创建； (2) 时间范围不对 — 右上角改时间范围到 Last 15 minutes 或 Last 7 days； (3) 索引名不匹配 — Data View 的索引模式要和 ES 中的索引名对应。

2. Grafana — 统一可视化平台

Grafana 默认端口 3000，访问 http://localhost:3000，默认账号 admin/admin。和 Kibana 不同，Grafana 不绑定特定存储后端，可以连接 Prometheus、Loki、Tempo、Elasticsearch、MySQL 等几十种数据源。

🔌 添加数据源（第一步）

  1. 左侧齿轮图标 → Data Sources → Add data source
  2. 选择 Prometheus（或其他数据源类型）
  3. 在 URL 栏填写 http://localhost:9090（Prometheus 的地址）
  4. 点击 Save & Test，看到绿色提示即连接成功

常见支持的数据源：

数据源用途URL 示例
Prometheus指标查询http://prometheus:9090
Loki日志查询http://loki:3100
Tempo追踪查询http://tempo:3200
Elasticsearch日志+搜索http://es:9200

📈 创建第一个 Dashboard

  1. 左侧 + 号图标 → New Dashboard → Add visualization
  2. 选择之前添加的数据源（如 Prometheus）
  3. 在查询编辑器中输入 PromQL：rate(http_requests_total[5m])
  4. 右侧面板设置：Title（图表标题）、Unit（单位）、Legend 显示模式
  5. 右上角 Apply → Save dashboard，取个名字
小贴士：Dashboard 右上角的 Time range 控制所有图表的时间范围。 点击 Refresh 可设置自动刷新间隔如 5s、10s。 Variables（变量）功能可以创建下拉筛选器，比如按 service 名过滤。

🧪 Explore（探索模式）

Explore 是 Grafana 的"调试台"，不需要先建 Dashboard 就能直接查询。

  1. 左侧罗盘图标 → Explore
  2. 顶部选择数据源（可以选 Mixed 同时查多个数据源）
  3. 输入查询语句，结果实时展示在右侧
  4. 支持在 Table 和 Graph 视图间切换
  5. 点击 Add to dashboard 可将当前查询保存为面板

🔔 Alerting（告警）

Grafana 8.x+ 内置统一告警系统：

  1. 左侧铃铛图标 → Alerting → Alert rules → New alert rule
  2. 选择数据源和查询（比如 up == 0 表示服务宕机）
  3. 设置触发条件：WHEN last() OF query(A, 5m) IS ABOVE 0
  4. 设置通知渠道：Email、Slack、PagerDuty、Webhook 等
  5. 保存后告警规则即生效
常见误区：Grafana 默认不存储数据，它只是"查询+展示"引擎。 数据存在 Prometheus/Loki/ES 等后端。所以 Grafana 重启不会丢 Dashboard 配置， 但如果 Prometheus 挂了，Grafana 上就看不到数据了。

3. Prometheus — 指标采集与查询

Prometheus 自带了简单的 Web UI，访问 http://localhost:9090 就能看到。虽然没有 Grafana 漂亮，但做调试和快速查询非常方便。

📝 Expression Browser（表达式浏览器）

这是访问 /graph 路径后看到的页面，左边输入框写 PromQL，右边展示结果。

  1. 输入 up — 查看所有监控目标是否在线（1=在线，0=离线）
  2. 输入 node_memory_MemTotal_bytes — 查看各节点总内存
  3. 输入 rate(http_requests_total[5m]) — 查看每秒请求速率

结果有两种展示模式：

  • Table — 表格展示当前值，适合查看精确数字
  • Graph — 折线图展示时间序列，适合观察趋势
小贴士：输入框支持自动补全！输入 up 后会列出所有匹配的 metric。 按 Shift + Enter 执行查询。右上角 Settings 可设置查询超时和要显示的指标数量。

🎯 Targets（监控目标页面）

在顶部菜单栏点击 Status → Targets（或访问 /targets）。

这个页面展示所有被 Prometheus 采集的目标及其状态：

  • ● UP — 采集正常，数据流畅通
  • ● DOWN — 无法连接，检查目标服务是否在运行
  • 每个目标行显示：Job 名、Endpoint URL、最后抓取时间、抓取耗时、错误信息
实用操作：如果目标显示 DOWN，点击错误链接可以看到具体报错信息。 可以用 up{job="your-job"} 在 Expression Browser 中查询该目标的在线状态。

⚙️ Service Discovery & Configuration

Status → Service Discovery 页面展示 Prometheus 如何发现采集目标，包括各 label 的值。这对于调试基于 K8s ServiceMonitor 的配置很有用。

Status → Configuration 页面展示当前生效的 prometheus.yml 配置，方便确认配置是否正确加载。

🔬 Flags & Runtime

Status → Command-Line Flags 显示启动参数。Status → Runtime 显示运行状态信息，包括时间戳、goroutine 数、存储使用量等，排查性能问题时有用。

4. Loki — 在 Grafana 中查看日志

Loki 本身没有独立 UI，通过 Grafana 的数据源插件来查询。确保已添加 Loki 数据源（http://loki:3100）。

🔍 在 Grafana Explore 中查询 Loki

  1. 进入 Grafana Explore，顶部数据源选 Loki
  2. 使用 LogQL 查询日志：{app="nginx"} |= "error"
  3. 结果会以时间轴 + 日志行列表展示
  4. 点击任一行日志可展开查看所有 label 和 metadata

两种查询模式：

  • Builder 模式 — 可视化拖拽，从下拉菜单选 label，适合新手
  • Code 模式 — 手写 LogQL，适合复杂查询
小贴士：Loki 的查询必须从 {label="value"} 开始（流选择器）， 不能像 ES 那样直接全文搜索。所以必须有 label 才能查到日志。 常用 LogQL 模式：{app="nginx"} |= "error" | json | status >= 500

📈 将日志转化为指标

LogQL 支持将日志行转为指标曲线，在 Explore 中切换到 Graph 视图即可：

rate({app="nginx"} |="error"[5m])

这行查询统计 nginx 每秒钟 error 日志的数量，可以加到 Dashboard 里和 Prometheus 指标放在一起对比。

5. Tempo — 在 Grafana 中查看追踪

Tempo 同样通过 Grafana 查询。添加 Tempo 数据源后：

🔬 查询 Trace

  1. 在 Grafana Explore 中选择 Tempo 数据源
  2. 三种查询方式：
    • Search — 按 service name / span name / 标签搜索 Trace
    • TraceQL — 用 TraceQL 语言精确查询，如 { resource.service.name = "frontend" && duration > 500ms }
    • TraceID — 直接粘贴 TraceID 查询
  3. 查询结果展示为水瀑布图（Waterfall），显示每个 span 的耗时和父子关系
  4. 点击 span 可查看详细信息和标签

🌐 Service Graph（服务拓扑图）

Tempo 的 Service Graph 功能将 Trace 数据转化为服务调用关系图：

  • 在 Grafana 配置 Tempo 数据源时，关联一个 Prometheus 数据源
  • Tempo 的 metrics-generator 从 trace 数据生成指标
  • 在 Grafana 中可以添加 Service Graph 面板，展示服务间的调用关系和请求量
  • 红色线表示有错误，粗线表示请求量大

🔗 Trace ↔ Logs ↔ Metrics 联动

Grafana 最强大的功能之一：从 Trace 跳转到对应日志，或从指标异常跳转到 Trace。

  • Trace → Logs：在 Tempo 数据源配置中设置，点击 span 即可跳转到对应时间范围的 Loki 日志
  • Metrics → Trace：在 Explore 中从 Prometheus 指标异常，点击后跳转到该时间点的 trace 详情
实际场景：在 Dashbord 中看到某个服务延迟突然飙升（Prometheus 指标）， 点击后跳转到 Tempo 查看是哪个端点慢了，再看该 trace 对应的日志找原因。 三部曲一气呵成。

6. 总结：各工具 UI 入口速查

工具URL最常用页面核心操作
Kibana :5601 Discover → Dashboard → Dev Tools 搜索日志、建可视化、调试 ES 查询
Grafana :3000 Explore → Dashboard → Alerting 建图表、查指标/日志/追踪、设置告警
Prometheus :9090 /graph → /targets → /rules 写 PromQL、查采集状态、看告警规则
Loki 通过 Grafana Grafana Explore (Loki 数据源) 换 LogQL 查日志、日志转指标
Tempo 通过 Grafana Grafana Explore (Tempo 数据源) 搜 Trace、看水瀑布图、服务拓扑
学习路线建议：
1️⃣ 先从 Prometheus UI 的 Expression Browser 开始，学写 PromQL（免费的调试场）
2️⃣ 再到 Grafana 把 Prometheus 数据源配上，建第一个 Dashboard
3️⃣ 加上 Loki 数据源，在同一个 Grafana 里查日志
4️⃣ 最后配 Tempo，实现全链路三信号联动
5️⃣ 一边用 Kibana 的 Dev Tools 练 ES Query DSL，熟悉后再建 Dashboard

UI 是工具的表层，重要的还是理解数据模型。PromQL、LogQL、ES DSL 会写之后， 工具只是不同的"展示壳"而已。
